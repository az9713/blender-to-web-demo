The project we are handing off

Build a small, genuine Blender-to-web demonstration: generate a concept image, construct a three-band mathematical sculpture in Blender, export a GLB, and load it into a plain Three.js webpage whose individual parts follow the mouse.

Implementation status: complete. The repository now includes the concept image, deterministic Blender script, editable .blend file, exported GLB, interactive Three.js site, and verification evidence. This document preserves the implementation specification and project knowledge; it is not a live ChatGPT session transfer.

User decisions and constraints

  • The objective is to demonstrate and understand the entire data-transformation workflow, not to win a website design competition.
  • Use Astra as the reasoning/coding agent, Blender as the 3D authoring engine, and Three.js as the web renderer. The agent invokes an available image-generation tool for the initial concept; do not assume Astra itself is the image-generation model.
  • Do not install or rely on Chase’s skill, Blender Agent Studio, Blender MCP, image-to-3D services, purchased models or external workflow frameworks. This is not a request to create a new skill.
  • Blender is already installed on the user's Windows computer, according to the user. Its path, version and access permissions still need to be verified by the executing local agent.
  • The bands must move independently in response to pointer movement. Rotating the entire sculpture as one object does not satisfy the request.
  • Use harmonic geometry, twisted strap-like cross-sections and spring dynamics. The mathematical identity is the distinctive feature.
  • Produce a runnable local project with all source files, intermediate assets and verification evidence. Public deployment is optional and needs an explicit request.

Export contract

Use uncompressed GLB for the first working version. Avoid Draco, KTX2 and custom decoders until there is a demonstrated need. Geometry, hierarchy and supported metallic/roughness material values must transfer. Keep Blender world lighting, render settings, Python scripts and complex shader graphs out of that assumption. Build the browser camera and lighting explicitly.

Material transfer is not pixel equivalence: Blender and the web renderer may use different lighting, tone mapping and exposure. Compare material parameters and silhouette, then tune web lighting rather than replacing every imported material.

A responsive three-band energy sculpture

Three thin metallic straps encircle a luminous core. Each loop has slight radial lobes, non-planar undulation and an independently controlled twist. The page is a technical demo, not a fictional business.

Minimal page

A title, one large interactive canvas, “Move pointer · Scroll to separate · Click to pulse,” a short explanation of the data pipeline, and Pulse / Pause / Reset / Wireframe controls are sufficient. Use a modest scroll section if needed. Include a loading indicator, clear error message and Blender-rendered fallback image. No testimonials, invented performance claims or business copy.

Rendering and materials

Use Principled-style metallic/roughness materials at authoring time. Suggested metalness: 0.92–1.00; roughness: outer 0.22, middle 0.18, inner 0.25. Use distinct base colors, without painting light highlights into them.

Two important rendering details: an emissive sphere is not automatically a light illuminating nearby objects in standard real-time rendering, and an emissive material does not automatically produce a halo. Add an actual light if the core should illuminate the bands; bloom is optional. Provide a procedural environment/reflection setup using Three.js’s own tools so metallic surfaces remain legible. Material reference.

Retain each imported material for baseline transfer verification. Clone a material before changing one part independently if the importer has shared it. Browser post-processing, lighting and shader patches are web-side behavior, not proof that Blender exported those effects.

Complete mathematical specification

Authoring geometry is static and reproducible. Browser interaction evolves rigid-body state. All angles are radians unless marked in degrees; all lengths are dimensionless scene units; time is in seconds.

Geometry · Closed frame · Clearance · Dynamics · Trackball · Pulses · Corrections

1Surface and centerline

Let band indices 1, 2, 3 denote outer, middle, inner. The core radius is 0.72. Parameters u and θ run around the loop and its cross-section, respectively.

All harmonic frequencies are integers, so the loop closes. Require |ε| + |η| < 1 to keep the radial function positive. Radial positivity makes the centerline simple in projection, but does not by itself guarantee that a thick swept surface cannot intersect itself.

2Orientations and coordinate conventions

Use a canonical right-handed assembly frame with Y up and the rest camera looking approximately along −Z. The unrotated loop lies in XY, so it faces this camera. “Outer/middle/inner” refers to radius, not whether a band is horizontal.

The standard Z-up→Y-up mapping is (x, y, z)Blender → (x, z, −y)web. Construct canonical points, map them into Blender with Cᵀ, and let the configured glTF exporter supply its normal axis conversion. Verify with axis-marker test points after loading. Do not rotate the loaded asset a second time by habit. Export options can change this convention.

3Tangent and transport frame

A curvature-based Frenet normal t′/‖t′‖ is ill-defined at zero curvature and can flip. Use a discrete rotation-minimizing transport frame instead. Sample N loop locations plus one duplicate endpoint for the frame-closure calculation; the duplicate is not a separate mesh ring.

Use periodic indices (or analytic derivatives). Choose the coordinate axis e least parallel to t₀ and normalize e − (e·t₀)t₀ as the initial normal. Then:

If adjacent tangents are nearly equal, retain the prior normal and reproject it. Near-antiparallel tangents indicate undersampling or degenerate geometry: increase sampling / report a failure rather than dividing by a near-zero cross product.

4Closed-loop seam correction

Transporting a normal around a closed loop generally returns it with a residual rotation (holonomy). Integer artistic twists alone do not fix this seam. Compute the signed angle rotating the returned normal back to the initial normal:

This distributes the compensating twist by arc length. The result is a closed, minimally adjusted frame, not a strictly rotation-minimizing frame everywhere. Numerically verify f₁,N ≈ f₁,0 and f₂,N ≈ f₂,0 before adding intentional twist. Do not compare the final distinct sample N−1 directly to 0; those lie at different points.

5Intentional twist and rounded strap section

Set integer full-twist counts ℓ = (0, +1, −1), not half twists. q is also an integer. These preserve the selected oriented cross-section after the frame has first been closed.

p = 2 gives an ellipse; p ≈ 4–6 gives a rounded rectangle. Default p = 5, a broad width and narrow thickness. The surface is the sweep in §1, not three stock toruses. Snap numerical values very close to sin/cos zeros to zero before raising them to fractional powers.

7Sampling, topology and normals

Twelve cross-section points are a baseline, not a quality guarantee for a p=5 superellipse. If silhouette faceting is visible, use arc-length resampling of the cross-section or raise it to 24 points (27,648 band triangles total). Smooth shading cannot repair a faceted silhouette. Recalculate outward normals, reject degenerate faces, and test each band is closed/manifold. UV seams and sharp-normal boundaries can increase exported vertex counts.

It does not prove each band avoids intersecting itself: test nonadjacent triangles / use Blender BVH geometry checks, excluding adjacent shared faces. Also check curvature locally:

Do not add unbounded idle translation, pulse overshoot or wider scroll motion without re-evaluating these bounds. Smoothing translations by a non-overshooting first-order filter preserves their magnitude bounds. Camera motion does not change clearance.

9Pointer normalization and band targets

Normalize using the canvas bounding rectangle, not the whole browser window. x and y are pointer coordinates relative to the rectangle, and W/H its CSS-pixel width/height.

This softens edge response; tanh(1.2) ≈ 0.834, so the gains below deliberately do not attain their nominal maximum. Use the same convention in tests.

These are rotation vectors expressed in the same assembly frame, not Euler angles. On pointer exit, set z=0 and allow the spring to settle. A root-only pointer rotation is insufficient.

These are an artistic inertial model in rotation-vector coordinates, not a complete rigid-body simulation. ζ=1 is critical damping, 0<ζ<1 underdamped. Distinct parameter pairs alone do not mechanically couple the bands; coupling is a separate optional term.

Use fixed 1/120 s simulation steps with an accumulator, at most six steps per rendered frame; discard excess backlog after a long suspension and reset the time origin on resume. Integrating once per rendered frame with a fixed 0.06 blend gives different behavior at 30, 60 and 144 Hz. If a first-order filter is preferred for core motion or scroll smoothing, use:

This is the frame-rate-aware alternative to the earlier per-frame blend. Starting damping rates: core 10 s⁻¹; scroll translation 6 s⁻¹. Use no spring overshoot for clearance-bounded translations.

11Optional coupling in a shared frame

Coupling is optional, disabled until the independent baseline passes. These coefficients are very weak relative to ω². Compute all accelerations from the same prior state before updating any band. Mixing differently oriented per-band local frames would make the subtraction physically inconsistent.

12Quaternion composition and pivots

Put the interactive transform on a fresh identity pivot in the common assembly frame. Keep the loaded, frozen rest transform below it; bake the base orientation Qᵢ into geometry only once. If directly updating a single object instead, assembly-frame rotation corresponds to qinteractive ⊗ qrest. The reverse product gives a different, local-frame interpretation. Never apply both conventions.

Use a positive denominator; disable scroll separation if the section is not taller than the viewport. Section top y is measured relative to the viewport. Set the following bounded individual offsets, which are one-quarter of the earlier unconstrained proposal:

14Causal core-to-outer click pulse

For click time tc, use delays dcore=0, dinner=0.08, dmiddle=0.18, douter=0.28 s. These are pulse delays, distinct from the translation bounds also called d in §8; use named fields in code.

Mandatory: emissive pulse. Suggested gains for core/inner/middle/outer: 2.0/0.8/0.6/0.4, tune exposure to avoid clipping. Optional: uniform band scale pulse 0≤μ≤0.015; optional core scale ≤1.05. Scale the existing mesh; this is not a rebuild of the radius parameter. Restart the pulse on click (do not sum unbounded pulses). Rapid rotation impulses are optional, not needed to demonstrate the workflow.

15Core following and optional orbiting nodes

Use a camera-facing interaction plane, convert its intersection to the sculpture’s assembly frame, clamp the displacement to 0.12, and smooth with the first-order filter. Keep the camera fixed for the baseline. Proposed gain gc=0.08.

Optional orbit tilt: Rorbit=Rx(0.2m̃y)Rz(0.2m̃x). Integrate phase from speed, rather than recomputing phase as speed×wall-time when the mouse changes. All node points remain within 0.12+0.88+0.04=1.04 of the assembly center, below the inner-band lower bound 1.10626. A 5% core expansion remains inside the node orbit. Respect Pause and reduced-motion preferences.

15AVirtual trackball assembly rotation

Free dragging acts on the shared assembly root, not on the three spring pivots. Let the canvas rectangle have left/top coordinates (l,t), dimensions (w,h), and s=min(w,h). A pointer sample (cx,cy) is first mapped to centered trackball coordinates.

Project points inside the unit disk onto the front hemisphere. Points outside the disk are normalized onto its rim, preventing invalid square roots while retaining continuous directions beyond the visible sphere.

The projected camera-space vectors are rotated into world space. The shortest unit quaternion between the pointer-down vector and current vector is the drag delta.

Left-multiply the drag delta by the assembly orientation captured at pointer-down. Each band then composes the shared assembly orientation, its independent spring orientation, and its Blender-authored rest orientation. Successive drags can reach arbitrary orientations without Euler-angle clamps or gimbal lock. A movement threshold distinguishes a drag from the click-pulse gesture.

16Optional traveling light along a band

Not needed for the minimum demo. If added, export an arc-length UV coordinate ξ=s(u)/L, then animate the web material rather than assuming a Blender node network will transfer.

Use a narrow periodic pulse with duplicated UV seam vertices when needed. Keep a baseline material-transfer view before patching shaders. Official Three.js shader hooks/addons are allowed; no external shader framework is required.

17One combined model

Blender constructs Xᵢ and qi,rest once. Three.js updates the assembly quaternion qA, scroll offset pᵢ, pulse scale λᵢ, and independent spring quaternion qi,spring. The shared trackball transform changes the viewing orientation without remeshing geometry or replacing the distinct band motions.

Execution plan for the new local agent

Work through the gates in order. The first image must precede Blender modeling; do not silently substitute a later Blender render for the image-generation step.

Gate 0 — Verify the real environment

  1. Read the entire HTML, including inactive tabs. Inspect existing project files and AGENTS.md; preserve unrelated changes.
  2. Report actual OS, execution host and working directory. Do not infer local access from the user’s UI or the existence of this file.
  3. Discover the installed Blender executable. Run --version and a background Python smoke test; identify bundled Python and the glTF export operator.
  4. Check image generation, ability to view its result, browser access / screenshots and a simple local HTTP server.
  5. Choose a pinned Three.js version; core and every official addon must come from the same release. No particular latest version is assumed in this document.
  6. If access requires approval or permissions are blocked, stop and ask for the specific missing authority. Do not modify security settings or invent remote access.
There is no content question blocking this handoff. Questions at execution time are limited to facts the agent cannot discover: inaccessible project folder, unavailable image generation, restricted Blender execution or an unapproved dependency change. Do not claim all gates pass before testing them.

Gate 1 — Generate and inspect the concept

Use the prompt in Asset & behavior. Save the first actual concept image and prompt. Compare band count, silhouette, palette and separation. Write a short concept-to-geometry note explaining that the equations are authoritative where an image is ambiguous or impossible.

Gate 2 — Build the Blender asset

Write ordinary bpy Python and a parameter JSON file. Generate the closed transport frame, resolve the seam, sweep each band, create materials and named parts. Save the source scene, render front/side/three-quarter views and run geometry checks. Keep exportable meshes in an ExportAsset collection and render-only lights/camera/background separate.

Make the script repeatable by replacing only its own named collection/data, not clearing arbitrary user scenes. Use a fresh headless Blender process for generation. Build a small asymmetric axis-marker test asset if needed to establish the exporter’s coordinates, then exclude it from the final GLB.

Gate 3 — Export and inspect GLB

Export only the intended object collection/selection as GLB. Verify the operator arguments against the installed Blender version. Confirm named nodes survive, three band meshes are independently accessible, and material parameters and bounding boxes are sensible. Inspect the GLB header/JSON chunk and parse it through GLTFLoader. Record file size and a checksum.

Gate 4 — Build a plain Three.js page

Load the GLB, create the camera and explicit lights, then create per-band pivots. Implement the shared-frame rotation-vector spring model, bounded scroll offsets, pointer-following core and causal click pulse. Add Pause, Reset, Wireframe and a deterministic diagnostics display for test evidence. Do not regenerate replacement band geometry in JavaScript.

Gate 5 — Test and refine

Run numerical and browser checks in the Acceptance tab. Inspect screenshots and actual input-driven motion, not merely a successful HTTP response. Fix visible faceting, dark materials, wrong axes, seam defects and coupled-by-accident meshes. Add optional features only after the mandatory baseline passes.

Gate 6 — Deliver a reproducible project

Provide the local launch command, confirmed Blender path/version, source image, Python, parameters, .blend, .glb, webpage and verification report. Explain any untested hardware scenarios. Public deployment is not a default deliverable.

Numerical test details

  • Evaluate orthogonality and unit length of every transport-frame basis; test periodic centerline, twist and closure.
  • Verify all geometry and state arrays are finite. Report triangle counts before and after GLB export and explain legitimate vertex splitting.
  • Check the shell bounds for the configured radii, widths, modulations, translations and scales. If they fail, change parameters or implement a separately validated collision strategy; do not ship hidden intersections.
  • Use a deterministic cursor step at t=0 and compare rotation vectors at t=1,2,4,6 s across render schedules. A target tolerance of 10⁻³ rad is a starting point; identify the time discretization used.
  • With coupling disabled, after sufficient settling the actual rotation vectors should approach Aᵢz. With coupling enabled, equilibria differ; do not reuse the uncoupled target as an exact assertion.
  • At pointer (0.8,−0.5), before damping, expected rotation-vector targets are approximately outer (−0.0537,0.4094,−0.0320), middle (−0.2578,−0.1340,0.0893), inner (0.1826,−0.2828,0.2563) rad. Compute from tanh exactly in tests.

Performance goals, not promises

Start with a DPR cap of 1.5–2, no shadows or expensive post-processing unless needed, and no large image textures. Provisional budgets: GLB under 5 MiB, under 50,000 asset triangles and under 30 main-scene draw calls before optional bloom. Measure rather than claim 60 fps: report viewport, browser, GPU when available, asset size, draw calls, triangles and median / 95th-percentile frame times. Software-rendered cloud tests do not certify the target laptop's performance.
